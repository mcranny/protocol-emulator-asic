# Protocol Emulator ASIC V3 design

Approved design, 19 October 2026. The implementation plan is a separate document.

Working copy: `C:\Users\matthewc\Documents\Projects\protocol-emulator-asic`. All development,
testing and local GDS runs happen from this checkout.

## 1. Goal and scope

V3 is the submission for the Jane Street protocol emulator ASIC competition, due 18 January 2027.
The goal is a working chip with SRAM program memory, deadline-based pin timing, a 48 MHz clock, and
larger electrical and protocol margins than V2.

The organisers' FAQ says flexibility is judged first: can the chip be reprogrammed for protocols it
was not designed for? Protocols demonstrated, unique capability, and design and verification
approach follow. Fewer protocols with a strong architecture and verification approach is explicitly
competitive. The submission is a public repository with RTL, tests, and a passing GDS and precheck
from the Tiny Tapeout flow, plus architecture, ISA, toolchain, example, verification, and AI-use
documentation.

**In scope:** time-cursor architecture with pin cells; two programmable engines; one 256x32 SRAM
macro per engine; 32-bit ISA; shared bit-serial CRC/LFSR unit; triggered capture on the shared
timebase; 48-clock host SPI frame; 48 MHz; 8x4 tiles with a 6x4 fallback; Python toolchain; UART,
SPI and I2C firmware in both roles; WS2812 as the protocol the chip was not designed for; formal,
differential, mutation and protocol verification; FPGA prototype on an Arty A7-35T.

**Deferred:** low-speed USB (after the deadline; the CRC unit is included for it), 10 Mbit Ethernet,
1-Wire, an independent Rust model (conditional, see section 10), and Hardcaml.

**Clean break:** V3 has no V1 or V2 compatibility. The V1 RTL, V1 physical configuration, V1/V2
test suites, V1/V2 cycle-compatibility promises and the dual top leave the V3 tree. V2 remains
available as the `v2` tag, its release assets and the git history. The default README, `info.yaml`
and documentation describe V3 only.

## 2. Architecture

Engines decide what happens. Pin cells decide when it happens.

**Timebase.** One free-running 24-bit counter at 48 MHz, wrapping every 349.5 ms. Both engines, all
eight pin cells and capture use it. An 8-bit epoch counter extends it to 32 bits for capture and
host readout, spanning about 89 s.

**Pin cells.** Each protocol pin `uio[7:0]` has one cell:

- One pending slot `{due_time, value, oe}` written by the owning engine.
- When `due_time - now`, as a signed 24-bit value, reaches zero, the cell applies the slot and frees
  it. If the distance is already negative when the slot is written, the cell applies it immediately
  and sets that pin's sticky missed-deadline flag.
- Open-drain pins never drive high. A requested high becomes high impedance in the cell.
- Input path: two-flop synchronizer, optional three-sample filter on the engine-visible value, and
  the timestamp and polarity of the last edge. Capture records the raw synchronized value, as in V2.

**Engines.** Two engines with disjoint pin ownership and open-drain masks, changed only while both
are stopped. An engine can only write cells it owns. Each engine has its own 24-bit cursor,
initialized to `now` on START. The cursor changes only when firmware changes it.

**Capture.** 32 records on the shared 32-bit timestamp: raw synchronized input, outputs, enables and
engine flags. It observes and never controls execution.

**CRC/LFSR.** One shared unit: 16-bit polynomial, 16-bit state, MSB-first or LSB-first, one bit per
instruction. Shorter CRCs such as CRC-5 use the low bits. Engines arbitrate for it; it is used in
bursts at frame ends.

**Host.** SPI mode 0, MSB first, 48 clocks per frame: `cmd[7:0]`, `addr[7:0]`, `payload[31:0]`.
Responses arrive on the following frame. Reply bit 7 of the command byte flags rejection, so engine
selection uses another command-byte bit. Any frame length other than 48 is rejected. Pins: `ui[0]`
SCK, `ui[1]` CS_n, `ui[2]` MOSI, `uo[0]` MISO, `uo[2:1]` engine running, `uo[3]` aggregate error, as in V2.

**Queues.** Per engine: 16 TX bytes and 16 RX records, unchanged in behavior from V2.

## 3. ISA and fetch contract

**Word.** 32 bits, matching the SRAM width. Flat 6-bit opcode in `[31:26]`, 26-bit operand in
`[25:0]`. No sub-opcode escape. Unused opcodes are illegal. Reserved operand bits must be zero.

**State per engine.** R0-R3 at 24 bits; 24-bit OSR; 8-bit ISR; 24-bit cursor; two-entry return
stack; timeout, interrupt and missed-deadline condition flags.

**Instruction classes.** About 45 of the 64 opcodes are used:

| Class | Instructions |
|---|---|
| Control | NOP, HALT, JMP, BRC (condition), DJNZ, CALL, RET, FAIL |
| Registers | LI (2-bit register, 24-bit immediate), MOV, ADD, SUB, AND, OR, XOR, SHL, SHR, BREQ |
| Time | ADVANCE (24-bit immediate), ADVANCER (register), CURSORSET, CURSORGET, NOW |
| Pin commit | SET, OE, DRIVE, OUT, each with a 10-bit cursor offset |
| Input | SAMPLE, IN, EDGETIME, WAITEDGE, WAITFOR |
| Queues | PULL, PULLNB, RX |
| Events | MARK, WAITEVENT, CLEAREVENT, CLEARMISS |
| CRC | CRCCFG, CRCLOAD, CRCBIT, CRCGET |

The opcode table is one source file. It defines encoding, operand masks and timing class, and it
drives the assembler, the Python model and a generated Verilog include for the RTL legality check.

**Time rules.**

- `ADVANCE n` adds `n` to the cursor in one cycle and never stalls. It replaces V2 `DELAY`.
- Commit instructions write `{value, oe}` with `due_time = cursor + offset` to every pin in their
  mask. A 10-bit offset covers 0-1023 ticks (21.3 µs).
- A commit stalls until every pin it targets has a free slot. With depth-1 slots this throttles an
  engine to the pin's event rate and needs no separate synchronization instruction.
- Deadline comparison is signed 24-bit distance. The scheduling window is ±8,388,608 ticks
  (±174.8 ms). Firmware must keep the cursor within that window of `now`; longer delays use repeated
  `ADVANCE` and a wait, so a due time is never misread as past.
- `WAITEDGE` and `WAITFOR` stall until a qualifying timestamped edge or until `now` reaches a
  cursor-derived timeout, then set the timeout or interrupt flag. Waits never sample a pin on an
  arbitrary cycle.
- `EDGETIME` reads the last edge timestamp of a pin into a register.

**Fetch.** The SRAM read is registered: address on cycle N, data on N+1. The engine prefetches PC+1
every cycle, so straight-line code runs one instruction per cycle. A taken branch always costs two
cycles. `A_MEN` is low whenever the engine is stalled. `A_DLY` is tied high and all `A_BIST_*`
inputs are tied low.

**Program validity.** SRAM contents are undefined at power-up and after deselection. Each engine has
a 256-bit validity bitmap in flops. Fetching an unwritten word is a fatal error. START is rejected
unless all 256 bits are set. The loader writes every word, fills unused words with HALT and reads
the image back before START.

## 4. Memory and physical integration

**Macros.** Two `RM_IHPSG13_1P_256x32_c2_bm_bist`, one per engine, 416.64 x 118.78 µm each, about
98,977 µm² together. The macro exists in the CMOS5L PDK through the `sg13cmos5l_sram` symlink.

**Floorplan.** Both macros on the left edge of the die, signal-pin faces toward each other, fetch
wrappers in the channel between them. Engines, pin cells, host, capture and CRC to the right.

| Tiles | Die (µm) | Estimated utilization |
|---|---|---|
| 8x4 (target) | 1724.16 x 710.64 | about 55% |
| 6x4 (fallback) | 1289.28 x 710.64 | about 75% |

The estimates start from the measured V2 standard-cell area of 793,932 µm², remove 3,072 program
flops at about 52 µm², their access logic and associated hold cells, and add pin cells, cursors,
wider registers, validity bitmaps and CRC. They are replaced by measured values at first synthesis.
The 8x4 target utilization ceiling is 65%. 6x4 stays buildable from the same RTL until the 8x4
template is confirmed by email.

**Power.** The CMOS5L tile has vertical Metal4 VPWR/VGND stripes only. The macro's `VDD!`,
`VDDARRAY!` and `VSS!` are vertical Metal4 columns, and a stripe connects only where it lands on a
column.

- Read the column positions from this macro's LEF. Do not reuse the 512x32 values from the published
  walkthrough.
- Set `FP_PDN_VWIDTH`, `FP_PDN_VSPACING`, `FP_PDN_VPITCH` and `FP_PDN_VOFFSET` so stripes center on
  the columns. V2's 50 µm pitch does not.
- Two `PDN_MACRO_CONNECTIONS` entries per instance, for `VDD!` and `VDDARRAY!`.
- Feed every supply column unless a Metal4 pin sits above or below a macro; then use every other
  column.
- Check stripes on columns in the GUI and read the IR-drop report. An unpowered macro passes DRC and
  LVS.

**Integration.** `MACROS` entry with GDS, LEF, CDL and three Liberty corners mapped to LibreLane
names (the fast SRAM corner is characterized at -55 °C). 2 µm halo. Routing obstructions on
Metal2-Metal4 over each macro. One antenna diode per SRAM input before detailed placement. Magic
DRC off, KLayout DRC on with the CMOS5L deck, `ERROR_ON_ILLEGAL_OVERLAPS` off for the known overlaps
at the `VDD!`/`VDDARRAY!` boundary. Precheck accepts marker layers 25/0 and 16/0. Synthesis sees a
`(* blackbox *)` header; RTL and gate-level simulation use the PDK behavioral model with
`-DFUNCTIONAL`.

Reference: https://kdp1965.github.io/ihp-um-janestreet-prism/ihp_sram_macro.html

**Timing.** `CLOCK_PERIOD` 20.833 ns. Maximum transition constraint 1.5 ns. Placement and global-route
hold margin 0.10 ns. Signoff targets at all three corners: zero setup, hold, slew, capacitance and
fanout violations; worst fast-corner hold slack at least +0.10 ns; worst slow-corner register-to-
register setup slack at least +2 ns.

**Flow.** Stock Tiny Tapeout flow, run locally. Release evidence is a fresh run from RTL, not a
checkpoint resume: precheck, KLayout DRC, LVS, extracted all-corner timing and gate-level tests with
the SRAM model linked. No pad timing claims until Tiny Tapeout publishes CMOS5L pad data.

**Acceptance:** both macros powered and connected, fresh run passes every check above at 8x4, and
the 6x4 build either passes or its failure is documented.

## 5. Toolchain and firmware

**Package.** `protocol_emulator.v3`, Python 3.11, type-checked with mypy. It contains the opcode
table, assembler, image loader, host API, cycle-accurate model, protocol peers and scenario tools.
V2 Python code is not part of the V3 package.

**Timing constants.** The assembler computes cycles from seconds at 48 MHz, rejects non-integer
results outside a stated tolerance and records actual rate and error in the image.

| Target | Cycles | Result |
|---|---|---|
| UART 9600 | 5000 | exact |
| UART 115200 | 417 | 0.080% error |
| UART 1 Mbaud | 48 | exact |
| SPI 1 MHz | 24 high, 24 low | exact |
| I2C 100 kHz | 240 low, 240 high | 5.0 µs each; minimums 4.7 and 4.0 µs |
| I2C 400 kHz | 72 low, 48 high | 1.5 and 1.0 µs; minimums 1.3 and 0.6 µs |
| WS2812 bit 0 | 19 high, 41 low | 0.40 / 0.85 µs |
| WS2812 bit 1 | 38 high, 22 low | 0.79 / 0.46 µs |
| WS2812 reset | at least 14,400 low | at least 300 µs |

The 400 kHz split leaves 400 ns of high-time margin for open-drain rise time instead of meeting
the 0.6 µs minimum by a few nanoseconds.

**Firmware rule.** Schedule an edge, then advance the cursor by the interval. The loop body must
finish inside the interval; otherwise the next commit is late, applied immediately and flagged.
Happy-path tests require all missed-deadline flags clear. A separate test forces a late commit and
requires the flag and the edge.

**Programs.** UART TX and RX at 115200 and 1 Mbaud, including duplex across both engines. SPI
controller and target, modes 0-3. I2C controller and target at 100 and 400 kHz, plus bus clear.
WS2812 transmit. Each program emits assembly, a 256-word image and a trace checked by an independent
peer. A program larger than 256 words fails assembly.

**Loader and host.** Write all 256 words, read back, configure ownership, open-drain and watchers,
then START. `connect()` reads the V3 version word and refuses other versions.

**Acceptance:** every program assembles, fits, and passes its peer on the model and on RTL.

## 6. Verification

V3 keeps V2's structure: induction proofs, a cycle-accurate model checked every edge, independent
wire-level peers, a mutation gate and reset audits. The central property changes from "which
instruction retired" to "when the pin changed."

### Formal proofs

| Proof | Properties |
|---|---|
| Pin cell | Positive distance never fires early; zero distance fires that cycle; negative distance fires immediately and sets the missed flag; an occupied slot is never overwritten; open-drain never drives high; stopped or reset engines drive no enable |
| Engine | Fetch abstracted as an arbitrary word one cycle after the address; taken branch inserts exactly one bubble; FIFO bounds and ordering; return-stack bounds; ownership masking; commits only to owned pins |
| Memory wrapper | Address and data latency; `A_MEN` low while stalled; invalid word faults; START requires a full validity bitmap |
| CRC | `CRCBIT` matches the configured polynomial and direction for CRC-16/CCITT and USB CRC5 |
| Host SPI | Exactly 48 clocks accepted; other lengths rejected; two-flop synchronizers; response delivered on the next frame |
| Input filter | Three agreeing samples qualify a change, as in V2 |
| Capture | Record count, pointer and timestamp consistency on the shared timebase |
| Integration | Disjoint ownership, open-drain gating, reset and disable release outputs, atomic START, stopped-only program writes; engines and pin cells black-boxed |

**Bounded liveness**, as safety properties with counters: a stalled commit retires within its
distance; `WAITEDGE` and `WAITFOR` always end by match or timeout. `PULL` on an empty TX queue is the
only unbounded stall and is documented as host-dependent.

### Simulation and test

- **Differential:** Python model against RTL every cycle, including pin values. A pin change is legal
  only on a scheduled tick or a recorded miss. RTL against gate level. RTL against FPGA when the board
  is available.
- **SRAM:** read and write at address boundaries, back-to-back reads, one-cycle latency, partial bit
  mask, uninitialized contents, on RTL and gate level.
- **Protocol corner cases:** UART back-to-back frames, bad stop bits and reset mid-frame; SPI edge
  alignment, CS transitions and back-to-back transfers; I2C ACK and NACK, repeated START, STOP, bus
  busy, arbitration loss and stuck lines; invalid opcodes and boundary addresses; reset during active
  transactions.
- **Cross-engine:** simultaneous START, barriers expressed as cursors advanced to the same tick,
  events before, during and after synchronization, one engine reset or stalled while the other runs.
- **Constrained-random:** random legal programs from the opcode table and random protocol traffic,
  both engines active, queue boundaries, stalls, branches and waits, recorded seeds, minimized
  failures promoted to directed tests.
- **Functional coverage:** all opcodes and branch outcomes, SPI modes, UART framing and errors, I2C
  conditions, queue wraparound, capture triggers and wraparound, timebase wraparound, cross-engine
  contention.

### Mutation gate

Each mutation must fail a named test; compile or parser failures do not count. Unsigned deadline
compare; deadline firing one cycle early; missed deadline without flag; taken branch costing one
cycle; wrong branch target; validity bit never set; inverted SPI sampling edge; UART stop-bit
framing; queue boundary off by one; capture timestamp offset; CRC tap on the wrong side; missing
reset on a state register.

### Timing and signoff

Static timing at all three corners. Protocol rates checked against section 5. Gate-level simulation
with SDF on a reduced vector set. RTL-to-netlist equivalence attempted with `eqy` with SRAM macros
black-boxed; if that does not work with this flow, the fallback is the RTL-against-gate differential
simulation plus the source and netlist hash chain, and the write-up says which was used. Reset and unknown-state audit. GDS, netlist and source hashes recorded
for the fresh run.

### Required versus if on track

Required for submission: formal proofs and bounded liveness, differential model/RTL/gate, SRAM
tests, protocol corner cases, cross-engine tests, mutation gate, static timing, signoff and
provenance. If the required set is green: constrained-random, functional coverage, SDF gate-level
simulation and `eqy`.

## 7. FPGA prototype

**Status: limited until the board arrives. It never blocks other work.** The board is an Arty A7-35T
(XC7A35T) and has not been purchased. Architecture, RTL, model, firmware, SRAM integration,
formal work and the ASIC flow all proceed without it.

**Before the board.** Write and simulate the FPGA top: a BRAM program store with the same contract
as the SRAM wrapper (registered read, no simultaneous read and write, enable low while stalled), an
MMCM generating 48 MHz from 100 MHz (`CLKFBOUT_MULT` 12, divide by 25), a synchronized reset button
used as `rst_n`, and a UART-to-SPI bridge that drives the chip's real SPI pins from the Python host.

**With the board.** The A7-35T fits the design. Its block RAM limits the ILA to about 2048 samples at
roughly 200 probe bits, so captures stay narrow and repeated. Before any protocol trace counts as
evidence, the ILA shows: fetch latency and a two-cycle taken branch; one pin cell committing on its
due tick, plus a forced late commit setting the missed flag; one 48-clock frame accepted and a
47-clock frame rejected. Then pin traces and capture records are compared against the model in
cycles. This does not verify pad delays or ASIC timing.

The existing `ice40up5k` workflow cannot fit the design and is retired.

**Acceptance:** wrapper simulation passes before the board. With the board, the three ILA checks
pass and every shipped program matches the model. If the board arrives too late, the write-up says
the FPGA comparison was not done.

## 10. Priorities and cut order

Critical path: architecture and ISA, then memory and physical integration, then toolchain and
firmware, then the required verification set, then the fresh flow run and submission package. FPGA
work runs alongside and is not on this path.

Decision points are outcomes, not dates:

- **48 MHz closure at 8x4.** An independent Rust model, as a second implementation of the ISA for
  model-only fuzzing and a browser demo, starts only after this closes with the required tests green.
  A Rust assembler is a low-risk option at any time.
- **8x4 template email.** Until it arrives, 6x4 stays buildable.

Cut order if time runs short: constrained-random and coverage; Rust model; SDF gate-level
simulation; `eqy` (fall back to differential simulation and hashes); FPGA comparison if the board is late.
Low-speed USB and 1-Wire are outside the submission.
